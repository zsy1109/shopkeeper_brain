## 1. 项目概述

### 1.1 项目背景

**项目名称**：智能知识库系统 (Intelligent Knowledge Base System)

**业务场景**：为企业客户提供一站式智能知识管理解决方案，涵盖文档自动化解析、多模态内容提取、语义检索、知识图谱问答等功能。

**核心价值**：
- **文档智能导入**：支持 PDF/Markdown 文档自动解析（MinerU Python API，解决中文路径编码）、图片描述提取（Qwen3-VL）、智能文档切分、向量化存储
- **语义检索**：基于 BGE-M3 混合向量的语义检索，兼顾语义理解和精确匹配
- **ReAct Agent 智能问答**：多轮 Tool Calling，Agent 主动调用本地知识库、联网搜索、价格查询等工具
- **多路检索融合**：向量检索、HyDE 假设文档检索、网络搜索三路并行，RRF 融合 + BGE-Reranker 重排序
- **流式响应**：SSE 实时推送查询进度和答案生成过程（Agent 流式 + LLM 流式双支持）

### 1.2 技术选型

#### 4.1.2 LLM 商品名提取器

```python
class ItemNameExtractor:
    """基于 LLM 的商品名提取器"""

    def extract_item_name(self, original_query: str, chat_history: List) -> Dict[str, Any]:
        # 1. 构造历史对话文本
        history_text = ""
        for msg in chat_history:
            role = msg.get("role")
            content = msg.get("text", "")
            history_text += f"{role}: {content}\n"

        # 2. 获取 LLM 客户端（支持 JSON 模式）
        llm_client = get_llm_client(response_format=True)

        # 3. 构造提示词
        human_prompt = ITEM_NAME_EXTRACT_TEMPLATE.format(
            history_text=history_text if history_text else "暂无上下文",
            query=original_query
        )
        system_prompt = "你是一个专业的客服助手，擅长理解用户意图和提取关键信息。"

        # 4. LLM 调用
        llm_response = llm_client.invoke([
            SystemMessage(content=system_prompt),
            HumanMessage(content=human_prompt)
        ])

        # 5. 清洗和解析 JSON 输出
        parsed_result = self._clean_parse(llm_response.content)

        return {
            "item_names": parsed_result.get("item_names", []),
            "rewritten_query": parsed_result.get("rewritten_query", original_query)
        }
```

#### 4.1.3 向量对齐器

```python
class ItemNameAligner:
    """向量对齐器 - 对 LLM 提取的商品名进行向量检索确认"""

    def match_align_filter(self, item_names: List[str]) -> Tuple[List[str], List[str]]:
        # 1. 查询向量数据库
        search_result: List[Dict[str, Any]] = self._match_vector(item_names)

        # 2. 评分对齐
        confirmed, options = self._item_name_score_align(search_result)

        # 3. 分数差异过滤
        if len(confirmed) > 1:
            confirmed = self._item_name_score_filter(confirmed, search_result)

        return confirmed, options

    def _match_vector(self, item_names: List[str]) -> List[Dict[str, Any]]:
        """对 LLM 提取的每个商品名进行向量检索"""
        # 1. 获取模型和客户端
        milvus_client = get_milvus_client()
        embedding_model = get_beg_m3_embedding_model()

        # 2. 批量生成混合向量
        hybrid_embedding_result = generate_hybrid_embeddings(
            embedding_model, item_names
        )

        # 3. 对每个商品名进行检索
        search_results = []
        for index, extract_item_name in enumerate(item_names):
            # 3.1 创建混合检索请求
            hybrid_search_requests = create_hybrid_search_requests(
                dense_vector=hybrid_embedding_result['dense'][index],
                sparse_vector=hybrid_embedding_result['sparse'][index],
            )

            # 3.2 执行混合检索
            hybrid_search_result = execute_hybrid_search_quest(
                collection_name="kb_item_names_v2",
                milvus_client=milvus_client,
                search_requests=hybrid_search_requests,
                ranker_weights=(0.5, 0.5),  # 稠密和稀疏各占 50%
                norm_score=True,           # 归一化分数
                output_fields=["item_name"]
            )

            # 3.3 解析结果
            item_name_search_result = {
                "extracted_name": extract_item_name,
                "matches": [
                    {"item_name": h["entity"]["item_name"], "score": h["distance"]}
                    for h in (hybrid_search_result[0] if hybrid_search_result else [])
                ]
            }
            search_results.append(item_name_search_result)

        return search_results
```

#### 4.1.4 评分对齐算法

```python
def _item_name_score_align(self, search_results: List[Dict[str, Any]]) -> Tuple[List[str], List[str]]:
    """
    评分对齐 - 根据向量检索分数将商品名分配到 confirmed 或 options

    阈值规则：
    - confirmed: score >= 0.7
    - options: 0.6 <= score < 0.7
    - 最多返回 3 个 options
    """
    confirmed = []
    options = []

    for item_name_search_result in search_results:
        extracted_name = item_name_search_result.get('extracted_name')
        matches = sorted(item_name_search_result.get('matches'), key=lambda x: x['score'], reverse=True)

        # 高分区间 (>= 0.7)
        high = [m for m in matches if m.get('score') >= 0.7]

        if high:
            # 场景A: 精确匹配
            extract = next((h for h in high if str(h['item_name']) == extracted_name), None)
            if extract:
                picked = extract["item_name"]
                if picked not in confirmed:
                    confirmed.append(picked)
            # 场景B: 单个高分
            elif len(high) == 1:
                picked = high[0]["item_name"]
                if picked not in confirmed:
                    confirmed.append(picked)
            # 场景C: 多个高分 → 放入 options
            else:
                for h in high[:3]:
                    picked = h.get('item_name')
                    if picked not in options and picked not in confirmed:
                        options.append(picked)
        else:
            # 中分区间 (0.6 - 0.7)
            mid = [m for m in matches if
                   m['score'] >= 0.6 and m.get('item_name') not in options and m.get('item_name') not in confirmed]
            if mid:
                for m in mid[:3]:
                    picked = m.get('item_name')
                    options.append(picked)

    return confirmed, options[:3]
```

#### 4.1.5 分数差异过滤

```python
def _item_name_score_filter(self, confirmed: List[str], search_results: List[Dict[str, Any]]) -> List[str]:
    """
    分数差异过滤 - 将误判的商品名从 confirmed 剔除

    原理：如果最高分和某个商品的分数差距超过阈值(0.15)，则认为该商品是误判
    """
    # 1. 构建商品名 → 最高分 的映射
    item_name_score = {}
    for search_result in search_results:
        matches = search_result.get('matches')
        for m in matches:
            score = m.get('score')
            item_name = m.get('item_name')
            if item_name in confirmed:
                item_name_score[item_name] = max(item_name_score.get(item_name) or 0, score)

    # 2. 找出最高分
    max_score = max(item_name_score.values())

    # 3. 过滤掉与最高分差距 > 0.15 的商品
    return [name for name, score in item_name_score.items() if max_score - score <= 0.15]
```

#### 4.1.6 下游流程决策

```python

### 4.3 HyDE 检索节点

#### 4.3.1 HyDE 原理

**HyDE (Hypothetical Document Embeddings)**：假设文档嵌入，通过 LLM 生成一个假设性的答案文档，然后对这个假设文档进行向量检索。

```
用户问题: "RS-12万用表如何测电压?"
         │
         ▼
    ┌─────────┐
    │   LLM   │ 生成假设文档
    └────┬────┘
         │ "要测量直流电压，首先将万用表拨到..."
         ▼
    ┌─────────┐
    │ BGE-M3  │ 对假设文档向量化
    └────┬────┘
         │
         ▼
    ┌─────────┐
    │ Milvus  │ 向量检索
    └────┬────┘
         │
         ▼
    与假设文档语义相似的文档片段
```

#### 4.3.2 节点实现

        """通过纯 httpx 同步调用 MCP JSON-RPC（DashScope WebSearch）"""
        import httpx

        base_url = self.config.mcp_dashscope_base_url
        auth_key = self.config.openai_api_key

        # 1. 先 discover 可用工具
        discover_resp = httpx.post(
            base_url,
            headers={"Authorization": f"Bearer {auth_key}"},
            json={
                "jsonrpc": "2.0", "id": 0,
                "method": "tools/list", "params": {}
            },
            timeout=30.0,
        )
        # discover_resp.json() 得到 {"result": {"tools": [...], "nextCursor": null}}

        # 2. 调用搜索工具 (bailian_web_search)
        call_resp = httpx.post(
            base_url,
            headers={"Authorization": f"Bearer {auth_key}"},
            json={
                "jsonrpc": "2.0", "id": 1,
                "method": "tools/call",
                "params": {
                    "name": "bailian_web_search",
                    "arguments": {"query": query, "count": 2}
                }
            },
            timeout=60.0,
        )

        result = call_resp.json()
        content = result.get("result", {}).get("content", [])
        if not content:
            return []

        # 3. 解析搜索结果 JSON
        text = content[0].get("text", "{}")
        parsed = json.loads(text)
        pages = parsed.get("pages") or []

        return [
            {
                "title": page.get("title", ""),
                "url": page.get("url", ""),
                "snippet": page.get("snippet", "")
            }
            for page in pages if page.get("snippet")

### 4.5 RRF 融合节点

#### 4.5.1 RRF 算法原理

**RRF (Reciprocal Rank Fusion)**：倒数排名融合，用于合并多个排序结果。

```
公式: score(d) = Σ weight_i / (k + rank_i(d))

其中：
- d: 待评分的文档
- i: 第 i 路检索
- weight_i: 第 i 路的权重
- rank_i(d): 文档 d 在第 i 路中的排名
- k: 平滑参数（通常为 60）

示例：
文档 A 在向量检索中排第 1，在 HyDE 中排第 3，在联网搜索中排第 2
score(A) = 1.0/(60+1) + 1.0/(60+3) + 0.7/(60+2) = 0.0164 + 0.0159 + 0.0113 = 0.0436
```

#### 4.5.2 节点实现

```python
# processor/query_processor/nodes/rrf_merge_node.py

class RrfNode(BaseNode):
    name = "rrf_merge_node"

    def process(self, state: QueryGraphState) -> QueryGraphState:
        # 1. 获取三路结果（向量 + HyDE + 网络搜索）
        embedding_chunks = state.get('embedding_chunks') or []
        hyde_embedding_chunks = state.get('hyde_embedding_chunks') or []
        web_search_docs = state.get('web_search_docs') or []

        # 2. 归一化联网搜索结果为统一格式
        web_chunks = self._normalize_web_docs(web_search_docs)

        # 3. 汇总成检索源（含权重）
        search_resource = {
            "embedding_search_resource": (self._normalize_chunk(embedding_chunks), 1.0),
            "hyde_search_resource": (self._normalize_chunk(hyde_embedding_chunks), 1.0),
            "web_search_resource": (web_chunks, self.config.rrf_web_weight)   # 0.7
        }

        # 4. 执行 RRF 融合
        rrf_inputs = list(search_resource.values())
        rrf_merge_results = self._rrf_merge(
            rrf_inputs,
            smoothing_factor=self.config.rrf_k,      # k=60
            top_n=self.config.rrf_max_results        # top_n=30
        )

        # 5. 更新 state
        rrf_chunks = [doc for doc, _ in rrf_merge_results]
        state['rrf_chunks'] = rrf_chunks

        return state

    def _normalize_web_docs(self, web_docs: List[Dict]) -> List[Dict]:
        """将联网搜索结果转换为统一的 chunk 格式"""
        normalized = []
        for idx, doc in enumerate(web_docs):
            snippet = doc.get("snippet", "")
            title = doc.get("title", "")
            url = doc.get("url", "")
            normalized.append({
                "chunk_id": f"web_{idx}",
                "content": f"[{title}] {snippet}",
                "score": 1.0 - idx * 0.1,    # 联网搜索结果按顺序给分
                "item_name": "网络搜索",
                "metadata": {"source_url": url}
            })
        return normalized

    def _rrf_merge(self, rrf_inputs, smoothing_factor=60, top_n=30):
        """RRF 融合算法"""
        chunk_scores = {}
        chunk_data = {}
        for rrf_input, weight in rrf_inputs:
            for rank, doc in enumerate(rrf_input, 1):
                chunk_id = doc.get('chunk_id')
                if not chunk_id:
                    continue
                chunk_scores[chunk_id] = chunk_scores.get(chunk_id, 0) + weight / (smoothing_factor + rank)
                chunk_data.setdefault(chunk_id, doc)
        sorted_results = sorted(
            [(chunk_data[chunk_id], score) for chunk_id, score in chunk_scores.items()],
            key=lambda x: x[1], reverse=True
        )
        return sorted_results[:top_n]
```

> **与原版本差异**：去掉了知识图谱检索（kg_chunks）的权重项，增加了 `web_search_docs` 的归一化处理。权重配置改为 `rrf_web_weight`（默认 0.7）。联网搜索结果是 LLM 调用 MCP 后返回的，按顺序给分。

# processor/query_processor/nodes/rerank_node.py

class RerankNode(BaseNode):
    name = "rerank_node"

    def process(self, state: QueryGraphState) -> QueryGraphState:
        # 1. 获取用户查询
        user_query = state.get('rewritten_query') or state.get('original_query')

        # 2. 合并本地 RRF 结果和网络搜索结果
        merged_docs = self._merge_docs(state)

        # 3. BGE-Reranker 重排序
        ranked_docs = self._rerank_merged_docs(user_query, merged_docs)

        # 4. 断崖检测截断
        top_docs = self._cliff_cutoff(ranked_docs)

        state['reranked_docs'] = top_docs
        return state

    def _rerank_merged_docs(self, user_query: str, merged_docs: List[Dict]) -> List[Dict]:
        """使用 BGE-Reranker 重排序"""
        # 1. 构建 (query, doc) 对
        query_doc_pairs = [
            (user_query, merged_doc.get('content'))
            for merged_doc in merged_docs
        ]

        # 2. 获取重排序模型
        rerank_model = get_reranker_model()

        # 3. 计算相关性分数
        relevance_scores = rerank_model.compute_score(sentence_pairs=query_doc_pairs)

        # 4. 构建带分数的文档列表
        ranked_docs = [
            {**doc, "score": float(score)}
            for doc, score in zip(merged_docs, relevance_scores)
        ]

        # 5. 按分数排序
        ranked_docs = sorted(ranked_docs, key=lambda doc: doc["score"], reverse=True)

        return ranked_docs
```

#### 4.6.2 断崖检测截断算法

```python
def _cliff_cutoff(self, ranked_docs: List[Dict]) -> List[Dict]:
    """
    断崖检测截断：相邻得分差距超过阈值时截断

    原理：
    - 从 min_top_k 位置开始检查相邻文档的分数差
    - 如果绝对差距 >= abs_gap 或相对比例 >= ratio_gap，则截断
    - 最少保留 min_top_k 条，最多保留 max_top_k 条
    """
    if not ranked_docs:
        return []

    # 计算截断范围
    upper_bound = min(self.config.rerank_max_top_k, len(ranked_docs))  # 20
    lower_bound = min(self.config.rerank_min_top_k, upper_bound)      # 5

    cutoff_pos = upper_bound

    for i in range(lower_bound - 1, upper_bound - 1):
        current_score = ranked_docs[i].get('score')
        next_score = ranked_docs[i + 1].get('score')

        if current_score is None or next_score is None:
            continue

        # 绝对差距
        abs_gap = current_score - next_score
        # 相对差距
        rel_gap = abs_gap / (abs(current_score) + 1e-6)

        # 任一差距超过阈值即为断崖
        if abs_gap >= self.config.rerank_gap_abs or rel_gap >= self.config.rerank_gap_ratio:
            cutoff_pos = i + 1
            self.logger.info(f"断崖检测: 位置 {i + 1}, abs_gap={abs_gap:.4f}, rel_gap={rel_gap:.4f}")
            break

    return ranked_docs[:cutoff_pos]
```

class AnswerOutputNode(BaseNode):
    name = "answer_output_node"

    def process(self, state: QueryGraphState) -> QueryGraphState:
        if state.get("answer"):
            return state

        # ---- 关键：根据配置选择模式 ----
        use_agent = getattr(self.config, "enable_agent_mode", True)

        if use_agent:
            self.logger.info("Agent 模式已启用，使用 ReAct Agent 生成答案")
            self._generate_answer_with_agent(state)
        else:
            self.logger.info("使用普通 LLM 单次调用生成答案")
            self._generate_answer_llm(state)

        return state

    def _generate_answer_with_agent(self, state: QueryGraphState):
        # 1. 收集所有 context：RRF+Rerank 后的本地文档 + 历史对话
        reranked_docs = state.get('reranked_docs', [])
        context = self._build_context(reranked_docs)

        # 2. 构造 Agent 所需的 item_names 字符串
        item_names = ', '.join(state.get('item_names', []))

        # 3. 创建 ReAct Agent 实例
        from processor.query_processor.agent.react_agent import ReActAgent

        agent = ReActAgent(
            api_key=config.openai_api_key,
            base_url=config.openai_base_url,
            model=config.llm_model_name,
            tools=[
                KnowledgeBaseTool(config),
                WebSearchTool(config),
                PriceQueryTool(config),
                ProductCompareTool(config),
            ],
            max_turns=config.agent_max_turns,    # 默认 5
        )

        agent.set_preloaded_context(reranked_docs)

        # 5. 调用 Agent（会自动 push 进度到 SSE queue）
        query = state.get('rewritten_query') or state.get('original_query')
        final_answer = agent.invoke(
            user_query=query,

            sse_queue=state.get('sse_queue'),   # 可选，用于流式推送
            task_id=state.get('task_id'),

        prompt = ANSWER_PROMPT.format(
            context=context,
            history=self._format_history(state.get('history', [])),
            item_names=', '.join(state.get('item_names', [])),
            question=state.get('rewritten_query') or state.get('original_query')

        response = llm_client.invoke([
            SystemMessage(content="你是一个专业的产品技术支持助手。"),
            HumanMessage(content=prompt)
        ])
        state['answer'] = response.content.strip()

# utils/sse_utils.py

class SSEEvent:
    READY = "ready"         # 连接建立
    PROGRESS = "progress"   # 任务节点进度
    DELTA = "delta"         # LLM 流式输出增量
    FINAL = "final"         # 最终完整答案
    ERROR = "error"         # 错误信息
    CLOSE = "__close__"     # 关闭连接信号

# 全局 SSE 任务队列存储
_task_stream: Dict[str, queue.Queue] = {}

def create_sse_queue(task_id: str) -> queue.Queue:
    """创建并注册一个新的 SSE 队列"""
    q = queue.Queue()
    _task_stream[task_id] = q
    return q

def push_sse_event(task_id: str, event: str, data: Dict):
    """通过 task_id 推送事件到 SSE 队列"""
    stream_queue = get_sse_queue(task_id)
    if stream_queue:
        stream_queue.put({"event": event, "data": data})

async def sse_generator(task_id: str, request: Request) -> AsyncGenerator[str, None]:
    """SSE 生成器，用于 FastAPI 的 StreamingResponse"""
    stream_queue = get_sse_queue(task_id)
    if stream_queue is None:
        return

    loop = asyncio.get_running_loop()
    try:
        # 发送连接建立信号
        yield _sse_pack("ready", {})

        while True:
            # 检查客户端断开
            if await request.is_disconnected():
                break

            try:
                # 从队列获取消息（1秒超时）
                msg = await loop.run_in_executor(None, stream_queue.get, True, 1.0)
            except queue.Empty:
                continue

            event = msg.get("event")
            data = msg.get("data")

            # 关闭事件
            if event == SSEEvent.CLOSE:
                break

            # 推送 SSE 事件
            yield _sse_pack(event, data)

    finally:
        remove_sse_queue(task_id)

def _sse_pack(event: str, data: Dict) -> str:
    """打包 SSE 消息格式"""
    payload = json.dumps(data, ensure_ascii=False)
    return f"event: {event}\ndata: {payload}\n\n"
```

```python
# processor/import_processor/nodes/pdf_to_md_node.py

import contextlib
import io
from pathlib import Path

import click
from mineru.cli.client import main as mineru_main

class PdfToMdNode(BaseNode):
    name = "pdf_to_md_node"

    def process(self, state: ImportGraphState) -> ImportGraphState:
        import_file_path_obj, file_dir_obj = self._validate_state(state)

        exit_code = self._execute_mineru_parse(import_file_path_obj, file_dir_obj)
        if exit_code != 0:
            raise PdfConversionError("MinerU解析PDF失败", self.name)

        md_path = self._get_md_path(import_file_path_obj, file_dir_obj)
        state['md_path'] = md_path
        return state

    def _execute_mineru_parse(self, pdf_path: Path, output_dir: Path) -> int:
        """通过 Python API 调用 MinerU（而非 subprocess），解决中文路径编码问题"""
        args = [
            "-p", str(pdf_path),       # 输入 PDF
            "-o", str(output_dir),     # 输出目录
            "-b", "pipeline",          # CPU pipeline 模式（不用 GPU）
            "-m", "txt",               # 文本模式
            "-l", "ch",                # 中文
        ]

        exit_code = 0
        output_buf = io.StringIO()
        try:
            # 用 redirect_stdout/redirect_stderr 捕获 MinerU 输出
            with contextlib.redirect_stdout(output_buf), \
                 contextlib.redirect_stderr(output_buf):
                mineru_main(args=args, standalone_mode=False)
                # standalone_mode=False: 不让 click 调 sys.exit()
        except click.exceptions.Exit as e:
            exit_code = e.exit_code
        except Exception as e:
            self.logger.error(f"MinerU 解析异常: {e}")
            exit_code = 1

        for line in output_buf.getvalue().splitlines():
            self.logger.info(f"MinerU: {line}")

        return exit_code

    @staticmethod
    def _get_md_path(pdf_path: Path, output_dir: Path) -> str:
        """输出路径规则: <output_dir>/<pdf_name>/txt/<pdf_name>.md"""
        return str(output_dir / pdf_path.stem / "txt" / f"{pdf_path.stem}.md")
```

**为什么用 Python API 而不是 subprocess？**

| 方式 | 优点 | 缺点 |
|------|------|------|
| subprocess 命令行 | 实现简单 | **中文路径编码问题**，Windows 下 GBK → UTF-8 出错 |
| Python API（`mineru_main`） | 原生 Python 调用，**无编码问题**，可控异常 | 要理解 click 的 `standalone_mode=False` |

**MinerU 参数说明**：
```bash
# 旧版（老师项目）- 需 GPU、有编码问题
mineru -p <pdf> -o <dir> --source local

# 新版（你的项目）- CPU 模式、无编码问题
mineru -p <pdf> -o <dir> -b pipeline -m txt -l ch
```

def _find_img_context_with_limit(self, md_content: str, img_name: str, max_chars=200):
    """从MD文档中提取图片上下文信息"""
    re_pattern = re.compile(r"!\[.*?\]\(.*?" + re.escape(img_name) + r".*?\)")
    md_lines = md_content.split("\n")
    imgs_context = []

    for line_idx, line in enumerate(md_lines):
        if not re_pattern.search(line):
            continue

        # 向上查找最近的标题
        head_title = ""
        head_index = -1
        for i in range(line_idx - 1, -1, -1):
            if re.match(r"^#{1,6}\s+", md_lines[i]):
                head_title = md_lines[i]
                head_index = i
                break

        # 提取上文（自下而上，按段落）
        pre_content = md_lines[head_index + 1:line_idx]
        img_pre_context = self._extract_img_context_with_limit(
            pre_content, max_chars, direction="front"
        )

        # 提取下文（自上而下，按段落）
        post_content = md_lines[line_idx + 1:section_index]
        img_post_context = self._extract_img_context_with_limit(
            post_content, max_chars, direction="end"
        )

        imgs_context.append((head_title, img_pre_context, img_post_context))

    return imgs_context
```

**标题切分算法**：

```python
def _split_by_headings(self, md_content: str, file_title: str) -> List[dict]:
    """根据MD的标题（1-6级）进行切分"""
    in_fence = False
    body_lines = []
    sections = []
    current_level = 0
    current_title = ""
    hierarchy = [""] * 7  # hierarchy[1-6]存储各级标题

    heading_re = re.compile(r"^\s*(#{1,6})\s+(.+)")
    content_lines = md_content.split("\n")

    for content_line in content_lines:
        # 检查代码块围栏
        if content_line.strip().startswith("```") or content_line.strip().startswith("~~~"):
            in_fence = not in_fence

        match = heading_re.match(content_line) if not in_fence else None

        if match:
            # 保存上一个section
            if current_title or body_lines:
                parent_title = self._find_parent_title(hierarchy, current_level)
                sections.append({
                    "title": current_title if current_title else file_title,
                    "body": "\n".join(body_lines),
                    "file_title": file_title,
                    "parent_title": parent_title or current_title or file_title
                })

            # 更新当前标题
            level = len(match.group(1))
            current_level = level
            current_title = content_line
            hierarchy[level] = current_title

            # 清空下级标题
            for i in range(level + 1, 7):
                hierarchy[i] = ""

            body_lines = []
        else:
            body_lines.append(content_line)

    # 保存最后一个section
    if current_title or body_lines:
        sections.append({...})

    return sections
```

**递归切分与合并算法**：

```python
def split_and_merge(self, sections, max_content_length, min_content_length):
    """切分过长章节，合并过短章节"""

    # 1. 切分过长章节
    current_sections = []
    for section in sections:
        current_sections.extend(self.split_long_section(section, max_content_length))

    # 2. 合并过短章节（贪心累加算法）
    final_sections = self.merge_short_section(current_sections, min_content_length)

    return final_sections

def split_long_section(self, section, max_content_length):
    """使用RecursiveCharacterTextSplitter切分长内容"""
    title = section.get('title')
    body = section.get('body')

    total_length = len(title) + len(body)
    if total_length <= max_content_length:
        return [section]

    # 使用LangChain的递归切分器
    text_splitter = RecursiveCharacterTextSplitter(
        chunk_size=max_content_length,
        chunk_overlap=0,
        separators=["\n\n", "\n", "。", "！", "？", "；", ".", "!", "?", ";", " ", ""],
        keep_separator=False
    )

    texts = text_splitter.split_text(body)

    sub_sections = []
    for index, text in enumerate(texts):
        sub_sections.append({
            "title": f"{title}-{index + 1}",
            "body": text,
            "file_title": section.get('file_title'),
            "parent_title": section.get('parent_title'),
            "part": f"{index + 1}"
        })

    return sub_sections

def merge_short_section(self, current_sections, min_content_length):
    """贪心累加算法合并短章节"""
    current_section = current_sections[0]
    final_sections = []

    for next_section in current_sections[1:]:
        same_parent = (current_section['parent_title'] == next_section['parent_title'])

        if same_parent and len(current_section.get('body')) < min_content_length:
            # 合并body
            current_section['body'] = (
                current_section.get('body').rstrip() + "\n\n" + next_section.get('body').lstrip()
            )
            current_section['title'] = current_section['parent_title']
            current_section['part'] = 0
        else:
            final_sections.append(current_section)
            current_section = next_section

    final_sections.append(current_section)

    # 重新编号part
    return self._renumber_parts(final_sections)
```

def _prepare_item_name_context(self, chunks, config):
    """从前K个chunk中构建上下文"""
    result = []
    total = 0

    for index, chunk in enumerate(chunks[:config.item_name_chunk_k]):
        content = chunk.get('content')
        spices = f"【切片】- {index + 1} - {content}"
        result.append(spices)

        total += len(spices)
        if total > config.item_name_chunk_size:
            break

def _recognition_item_name_by_llm(self, file_title: str, item_name_context: str) -> str:
    """使用LLM识别商品名"""
    llm_client = get_llm_client()
    if llm_client is None:
        return file_title  # 降级回退

    prompt = ITEM_NAME_USER_PROMPT_TEMPLATE.format(
        file_title=file_title,
        context=item_name_context
    )

    try:
        llm_response = llm_client.invoke([
            SystemMessage(content=ITEM_NAME_SYSTEM_PROMPT),
            HumanMessage(content=prompt)
        ])

        item_name = llm_response.content.strip()
        if not item_name or item_name.upper() == 'UNKNOWN':
            return file_title  # 降级回退

        return item_name
    except Exception as e:
        self.logger.error(f"LLM调用失败，回退到文件标题: {e}")
        return file_title

def _embedding_item_name(self, item_name: str) -> Tuple[list, dict]:
    """使用BGE-M3嵌入商品名"""
    embedding_model = get_beg_m3_embedding_model()
    embedding_result = embedding_model.encode_documents([item_name])

    # 获取稠密向量
    dense = embedding_result['dense'][0].tolist()

    # 获取稀疏向量
    start_index = embedding_result['sparse'].indptr[0]
    end_index = embedding_result['sparse'].indptr[1]
    weights = embedding_result['sparse'].data[start_index:end_index].tolist()
    tokenIds = embedding_result['sparse'].indices[start_index:end_index].tolist()
    sparse = dict(zip(tokenIds, weights))

        "file_title": file_title,
        "item_name": item_name,
        "dense_vector": dense_vector,

        # 1. 参数校验

        # 2. 获取批量大小
        batch_size = getattr(config, 'embedding_batch_size', 16)

        # 3. 分批嵌入
        final_chunks = []
        total_length = len(validated_chunks)

        for i in range(0, total_length, batch_size):
            batch = validated_chunks[i:i + batch_size]
            batch_chunks = self._process_batch_chunks(batch, i, total_length)
            final_chunks.extend(batch_chunks)

        state['chunks'] = final_chunks
        return state

    def _process_batch_chunks(self, batch, start_index, total_length):
        """处理一个批次的chunks"""
        # 1. 准备嵌入��容
        embedding_contents = []
        for chunk in batch:
            content = chunk.get('content')
            item_name = chunk.get('item_name')
            embedding_content = f"{item_name}\n{content}"
            embedding_contents.append(embedding_content)

        # 2. 批量嵌入
        bge_m3_model = get_beg_m3_embedding_model()
        embedding_result = bge_m3_model.encode_documents(documents=embedding_contents)

        # 3. 将向量注入到每个chunk
        for index, chunk in enumerate(batch):
            # 3.1 获取稠密向量
            dense_vector = embedding_result['dense'][index].tolist()

            # 3.2 获取稀疏向量
            csr_array = embedding_result['sparse']
            ind_ptr = csr_array.indptr
            start_ind_ptr = ind_ptr[index]
            end_ind_ptr = ind_ptr[index + 1]
            token_id = csr_array.indices[start_ind_ptr:end_ind_ptr].tolist()
            weight = csr_array.data[start_ind_ptr:end_ind_ptr].tolist()
            sparse_vector = dict(zip(token_id, weight))

            # 3.3 注入到chunk
            chunk['dense_vector'] = dense_vector
            chunk['sparse_vector'] = sparse_vector

        return batch
```

```python
def _process_single_chunk(self, chunk_id: str, item_name: str, content: str,
                          milvus_client: MilvusClient, neo4j_driver) -> Tuple[int, int]:
    """处理单个chunk：LLM提取 → 解析清洗 → 写入Milvus → 写入Neo4j"""

    # 1. LLM提取（带重试机制）
    llm_response = self._extract_graph_with_retry(content)

    # 2. 解析和清洗
    graph_result = self._parse_and_clean(llm_response)
    final_entities = graph_result.get('entities')
    final_relations = graph_result.get('relations')

    # 3. 写入Milvus（实体向量化）
    self._milvus_writer.insert(milvus_client, final_entities, chunk_id, content, item_name, self._embedding_lock)

    # 4. 写入Neo4j（实体+关系）
    self._neo4j_writer.insert(neo4j_driver, final_entities, final_relations, chunk_id, item_name)

    return len(final_entities), len(final_relations)

**LLM提取（带重试）**：

```python
def _extract_graph_with_retry(self, content: str) -> str:
    """提取图谱信息，失败时重试3次"""
    llm_client = get_llm_client()
    MAX_COUNT = 3

    for attempt in range(1, MAX_COUNT + 1):
        try:
            llm_response = llm_client.invoke([
                SystemMessage(content=KNOWLEDGE_GRAPH_SYSTEM_PROMPT),
                HumanMessage(content=f"切片信息\n\n{content}")
            ])

            result = llm_response.content.strip()
            if result:
                return result
        except Exception as e:
            if attempt < MAX_COUNT:
                delay = 0.5 * (2 ** (attempt - 1))  # 指数退避
                self.logger.warning(f"开始第{attempt}次重试，间隔：{delay:.1f}s")
                time.sleep(delay)

    return ""  # 兜底
```

**实体和关系清洗**：

```python
def _parse_and_clean(self, llm_response: str) -> Dict[str, Any]:
    """解析LLM输出并清洗实体和关系"""

    # 1. 清洗JSON代码块围栏
    cleaned = re.sub(r"^```(?:json)?\s*", "", llm_response.strip())
    cleaned = re.sub(r"\s*```$", "", cleaned)

    # 2. 反序列化
    parsed_llm_response = json.loads(cleaned)

    # 3. 获取实体和关系
    entities = parsed_llm_response.get('entities', [])
    relations = parsed_llm_response.get('relations', [])

    # 4. 清洗实体
    cleaned_entities = self._clean_entities(entities)

    # 5. 获取唯一的实体名集合
    cleaned_unique_entity_names = {entity.get('name') for entity in cleaned_entities}

    # 6. 清洗关系
    cleaned_relations = self._clean_relations(cleaned_unique_entity_names, relations)

    return {"entities": cleaned_entities, "relations": cleaned_relations}

def _clean_entities(self, entities: List[Dict]) -> List[Dict]:
    """清洗实体：长度限制、白名单过滤、去重"""
    ALLOWED_ENTITY_LABELS = {
        "Device", "Part", "Operation", "Step",
        "Warning", "Condition", "Tool",
    }

    unique_seen = set()
    clean_entities_result = []

    for entity in entities:
        entity_name = str(entity.get('name', '')).strip()
        if not entity_name:
            continue

        # 长度限制
        if len(entity_name) > MAX_ENTITY_NAME_LENGTH:
            entity_name = entity_name[:15]

        # 白名单过滤
        entity_label = str(entity.get('label', '')).strip()
        if entity_label not in ALLOWED_ENTITY_LABELS:
            continue

        # 去重
        unique_key = (entity_name, entity_label)
        if unique_key in unique_seen:
            continue
        unique_seen.add(unique_key)

        clean_entity = {"name": entity_name, "label": entity_label}
        entity_describe = str(entity.get('description', '')).strip()
        if entity_describe:
            clean_entity['description'] = entity_describe

        clean_entities_result.append(clean_entity)

    return clean_entities_result
```

```python
class Neo4jGraphWriter:
    """负责将实体与关系写入Neo4j"""

    def insert(self, driver, entities, relations, chunk_id, item_name):
        """在单事务内完成 Chunk + Entity + Relation 的写入"""
        with self._session(driver) as session:
            session.execute_write(
                self._write_graph_tx, entities, relations, chunk_id, item_name
            )

    def _write_graph_tx(self, tx, entities, relations, chunk_id, item_name):
        """事务内写入全部数据"""

        # 1. 创建Chunk节点
        tx.run(CYPHER_MERGE_CHUNK, chunk_id=chunk_id, item_name=item_name)

        # 2. 创建实体节点并关联到Chunk
        for entity in entities:
            name = entity.get("name")
            raw_label = entity.get("label")
            description = entity.get("description", "")

            # 动态格式化Cypher
            cypher_query = CYPHER_MERGE_ENTITY_TEMPLATE.format(label=raw_label)
            tx.run(cypher_query, name=name, description=description,
                   chunk_id=chunk_id, item_name=item_name)

            # 关联到Chunk
            tx.run(CYPHER_LINK_ENTITY_TO_CHUNK, name=name,
                   chunk_id=chunk_id, item_name=item_name)

        # 3. 创建实体间关系
        for rel in relations:
            head = rel.get("head")
            tail = rel.get("tail")
            rel_type = rel.get("type")

            cypher = CYPHER_MERGE_RELATION_TEMPLATE.format(rel_type=rel_type)
            tx.run(cypher, head=head, tail=tail, item_name=item_name)
```

```python
def _process_chunks_concurrently(self, stats, validated_chunks, milvus_client, neo4j_driver):
    """使用线程池并发处理所有切片"""
    with ThreadPoolExecutor(max_workers=4) as pool:
        future_to_idx = {}

        # 提交所有任务
        for i, chunk in enumerate(validated_chunks):
            chunk_id = str(chunk.get("chunk_id"))
            item_name = chunk.get("item_name")
            content = chunk.get("content")

            future = pool.submit(
                self._process_single_chunk,
                chunk_id, item_name, content, milvus_client, neo4j_driver,
            )
            future_to_idx[future] = (i, chunk_id)

        # 收集结果
        for future in as_completed(future_to_idx):
            idx, chunk_id = future_to_idx[future]
            try:
                entity_count, relation_count = future.result()
                stats.processed_chunks += 1
                stats.total_entities += entity_count
                stats.total_relations += relation_count
            except Exception as e:
                stats.failed_chunks += 1
                stats.errors.append(f"切片 {chunk_id} 处理失败: {e}")
```

### 4.10 ReAct Agent 智能体模块 🆕

#### 4.10.1 什么是 ReAct 模式？

**ReAct (Reasoning + Acting)** 是一种让 LLM 既能"思考"又能"行动"的 Agent 范式：

```
传统 RAG:  用户问题 → 检索文档 → LLM 单次生成答案（信息不够也没办法补）

ReAct Agent:
    用户问题
      └─→ LLM 思考：我需要哪些信息？
            ├─ 直接回答（信息已足够）→ 输出答案
            └─ 需要补充 → 调用工具（Function Calling）
                            ├─ search_knowledge_base()
                            ├─ search_web()
                            ├─ get_realtime_price()
                            └─ compare_products()
            └─ 拿到工具结果 → 继续思考 → 继续调工具或输出答案
            └─ 最多 MAX_TURNS 轮，达到上限也会输出
```

#### 4.10.2 核心架构

```
knowledge/processor/query_processor/
├── agent/
│   ├── __init__.py
│   └── react_agent.py            # ReActAgent 主引擎
├── tools/

│   └── query_tools.py             # 4 个具体工具实现

```python
# processor/query_processor/tools/base.py

class AgentTool:
    """所有 Agent 可调用工具的基类。"""
    name: str = ""          # 工具唯一标识
    description: str = ""   # 告诉 LLM 这个工具能干嘛
    parameters: Dict = {}   # JSON Schema 格式的参数定义

    def run(self, **kwargs) -> Any:
        """子类必实现：真正的业务逻辑。"""
        raise NotImplementedError

    def tools_json_schema(self) -> Dict:
        """生成 Function Calling 所需的 tools schema。"""
        return {
            "type": "function",
            "function": {
                "name": self.name,
                "description": self.description,
                "parameters": self.parameters,
            },
        }

    def safe_run(self, **kwargs) -> str:
        """包装 run：捕获异常 + 自动 JSON 序列化。"""
        try:
            result = self.run(**kwargs)
            if isinstance(result, str):
                return result
            return json.dumps(result, ensure_ascii=False, default=str)
        except Exception as e:
            logger.error(f"Tool {self.name} execution failed: {e}")
            return json.dumps({"error": str(e)}, ensure_ascii=False)


class ToolRegistry:
    """工具注册表：可以统一管理所有 Agent 工具。"""
    _tools: Dict[str, AgentTool] = {}

    @classmethod
    def register(cls, tool: AgentTool):
        cls._tools[tool.name] = tool

    @classmethod
    def all_schemas(cls) -> List[Dict]:
        return [t.tools_json_schema() for t in cls._tools.values()]
```

#### 4.10.5 ReActAgent 引擎核心循环

```python
# processor/query_processor/agent/react_agent.py

class ReActAgent:
    MAX_TURNS = 5

    def __init__(self, api_key, base_url, model, tools,
                 max_turns=MAX_TURNS, system_prompt=AGENT_SYSTEM_PROMPT):
        self._api_key = api_key
        self._base_url = base_url.rstrip("/")
        self._model = model
        self._tools = {t.name: t for t in tools}             # {name → instance}
        self._tool_schemas = [t.tools_json_schema() for t in tools]
        self._max_turns = max_turns
        self._system_prompt = system_prompt

    def invoke(self, user_query: str, context: str = "",
               item_names: str = "") -> str:
        # Step 1: 构建初始 messages
        messages = self._build_initial_messages(user_query, context, item_names)
        final_text = ""

        # Step 2: 多轮 ReAct 循环
        for turn in range(self._max_turns):
            # 调 LLM（带 tools schema，让 LLM 选择是否调工具）
            llm_msg, tool_calls = self._call_llm(messages)

            # LLM 没有发起 tool_calls → 说明它认为信息够了，可以直接回答
            if tool_calls is None:
                final_text = llm_msg or ""
                break

            # LLM 发起了 tool_calls → 把 assistant 的回复加进 messages
            messages.append({
                "role": "assistant",
                "content": llm_msg,
                "tool_calls": tool_calls,
            })

            # Step 3: 执行所有 tool_calls
            tool_results = self._execute_tool_calls(tool_calls)
            for tc_id, tool_name, result_text in tool_results:
                messages.append({
                    "role": "tool",
                    "tool_call_id": tc_id,
                    "name": tool_name,
                    "content": result_text,
                })

        # 达到最大轮次还没 break → 取最后一条内容
        else:
            final_text = messages[-1].get("content", "") if messages else ""

        return final_text or "Agent 暂无法生成答案"

    def _call_llm(self, messages):
        """通过 httpx 直接调 /chat/completions，带 tools 参数。"""
        payload = {
            "model": self._model,
            "messages": messages,
            "tools": self._tool_schemas,       # 告诉 LLM 有哪些工具可用
            "tool_choice": "auto",              # 让 LLM 自己决定要不要调
            "temperature": 0.1,
        }
        r = httpx.post(
            f"{self._base_url}/chat/completions",
            headers={"Authorization": f"Bearer {self._api_key}",
                     "Content-Type": "application/json"},
            json=payload, timeout=120,
        )
        data = r.json()
        msg = data["choices"][0]["message"]
        return msg.get("content", "") or "", msg.get("tool_calls")

    def _execute_tool_calls(self, tool_calls):
        """遍历每个 tool_call，找到对应 AgentTool 实例，执行 safe_run。"""
        results = []
        for tc in tool_calls:
            tc_id = tc["id"]
            func = tc["function"]
            tool_name = func["name"]
            args_raw = func.get("arguments", "{}")

            tool = self._tools.get(tool_name)
            if not tool:
                results.append((tc_id, tool_name, json.dumps(
                    {"error": f"未知工具: {tool_name}"}, ensure_ascii=False)))
                continue

            try:
                args = json.loads(args_raw) if isinstance(args_raw, str) else args_raw
            except JSONDecodeError:
                args = {}

            result_text = tool.safe_run(**args)  # safe_run 已封装异常处理
            results.append((tc_id, tool_name, result_text))

        return results

    def stream(self, user_query, context="", item_names="") -> Generator:
        """流式调用：只在最后一轮（无 tool_calls 时）才 yield 增量文本。"""
        messages = self._build_initial_messages(user_query, context, item_names)
        for turn in range(self._max_turns):
            llm_msg_deltas, tool_calls = self._call_llm_stream(messages)
            if tool_calls is None:
                # 最终答案：逐 delta yield 给 SSE
                for delta in llm_msg_deltas:
                    yield delta
                break
            # 中间轮：把 tool_calls 累积好后加入 messages，不 yield
            full_content = "".join(llm_msg_deltas)
            messages.append({"role": "assistant", "content": full_content, "tool_calls": tool_calls})
            for tc_id, tool_name, result_text in self._execute_tool_calls(tool_calls):
                messages.append({"role": "tool", "tool_call_id": tc_id, "name": tool_name, "content": result_text})

    def _call_llm_stream(self, messages):
        """流式 LLM 调用，边收 SSE 边累积 content 和 tool_calls。
        关键难点：tool_calls 的 name/arguments 是分片到达的，需要按 index 合并。"""
        payload = {"model": self._model, "messages": messages, "tools": self._tool_schemas,
                   "tool_choice": "auto", "temperature": 0.1, "stream": True}
        content_deltas = []
        accumulated_tool_calls = {}   # {index: tc_dict}
        finish_reason = None

        with httpx.stream("POST", f"{self._base_url}/chat/completions",
                          json=payload, timeout=120) as r:
            for line in r.iter_lines():
                if not line.startswith("data: "):
                    continue
                chunk = json.loads(line[6:])
                delta = chunk["choices"][0].get("delta", {})
                finish_reason = chunk["choices"][0].get("finish_reason")

                if delta.get("content"):
                    content_deltas.append(delta["content"])
                if "tool_calls" in delta:
                    for tc_delta in delta["tool_calls"]:
                        idx = tc_delta.get("index", 0)
                        if idx not in accumulated_tool_calls:
                            accumulated_tool_calls[idx] = {"id": "", "function": {"name": "", "arguments": ""}}
                        tc = accumulated_tool_calls[idx]
                        if tc_delta.get("id"):
                            tc["id"] = tc_delta["id"]
                        fn = tc_delta.get("function", {})
                        if fn.get("name"):
                            tc["function"]["name"] += fn["name"]
                        if fn.get("arguments"):
                            tc["function"]["arguments"] += fn["arguments"]

        if finish_reason == "tool_calls" and accumulated_tool_calls:
            return content_deltas, list(accumulated_tool_calls.values())
        return content_deltas, None
```

#### 4.10.7 Agent 相比普通 RAG 的优势

#### 5.1.2 BGE-M3 混合向量

**技术要点**：

# utils/bge_m3_embedding_util.py

def generate_hybrid_embeddings(embedding_model, embedding_documents):
    """生成混合向量"""
    embedding_result = embedding_model.encode_documents(embedding_documents)

    # 处理稀疏向量（CSR 矩阵 → 字典）
    processed_sparse_result = []
    csr_array = embedding_result['sparse']

    for index in range(len(embedding_documents)):
        ind_ptr = csr_array.indptr
        start_ind_ptr = ind_ptr[index]
        end_ind_ptr = ind_ptr[index + 1]

        token_id = csr_array.indices[start_ind_ptr:end_ind_ptr].tolist()
        weight = csr_array.data[start_ind_ptr:end_ind_ptr].tolist()

        sparse_vector = dict(zip(token_id, weight))
        processed_sparse_result.append(sparse_vector)

    return {
        "dense": [den.tolist() for den in embedding_result["dense"]],
        "sparse": processed_sparse_result
    }
```

#### 5.1.4 断崖检测截断算法

**技术要点**：
- **绝对差距检测**：相邻分数差值 >= 0.3
- **相对差距检测**：相邻分数比例 >= 50%
- **边界控制**：最少保留 5 条，最多保留 20 条
- **动态截断**：根据分数分布动态确定保留数量

**算法流程**：

```
1. 确定检查范围：[min_top_k, max_top_k] = [5, 20]
2. 从位置 5 开始，逐对检查相邻文档分数差
3. 如果 abs_gap >= 0.3 或 rel_gap >= 0.5，则截断
4. 返回截断前的文档列表

示例：
文档1: score=0.95
文档2: score=0.93
文档3: score=0.89
文档4: score=0.87
文档5: score=0.82  ← min_top_k，从这里开始检查
文档6: score=0.35  ← abs_gap=0.47 > 0.3，截断！
文档7: score=0.33
...

最终返回：文档1-5
```

def _item_name_score_filter(self, confirmed, search_results):

#### 5.2.5 LLM JSON 解析失败问题

```python
def _clean_parse(self, llm_response: str) -> Dict:
    # 1. 清洗 JSON 代码块围栏
    cleaned = re.sub(r"^```(?:json)?\s*", "", llm_response.strip())
    content = re.sub(r"\s*```$", "", cleaned)

    # 2. JSON 解析
    try:
        parsed = json.loads(content)
    except JSONDecodeError as e:
        raise ValueError(f"JSON 解析失败: {e}")

    # 3. 字段清洗
    item_names = parsed.get('item_names', [])
    if not isinstance(item_names, list):
        item_names = []
    else:
        item_names = [name for name in item_names if name.strip()]

    rewritten_query = parsed.get('rewritten_query', '')
    if not isinstance(rewritten_query, str):
        rewritten_query = ''

    return {"item_names": item_names, "rewritten_query": rewritten_query.strip()}
```

#### 5.2.2 PDF解析失败问题

**问题描述**：
用户上传的PDF文件格式多样，包含复杂表格、公式、图片等，直接解析可能导致内容丢失或格式错乱。此外，早期用 subprocess 调用 MinerU CLI 时，Windows 下中文路径（如 `万用表的使用.pdf`）会因为 GBK/UTF-8 编码冲突报 `UnicodeDecodeError`。

**解决方案 - MinerU Python API 直接调用**：

```python
# processor/import_processor/nodes/pdf_to_md_node.py

import contextlib
import io
import click
from mineru.cli.client import main as mineru_main

def _execute_mineru_parse(self, import_file_path_obj: Path, file_dir_obj: Path) -> int:
    """通过 Python API 调用 MinerU（而非 subprocess），解决中文路径编码问题"""
    args = [
        "-p", str(import_file_path_obj),
        "-o", str(file_dir_obj),
        "-b", "pipeline",        # 使用 pipeline 模式解析
        "-m", "txt",             # 输出 Markdown 格式
        "-l", "ch",              # 中文模型
    ]

    exit_code = 0
    output_buf = io.StringIO()
    try:
        # redirect_stdout/stderr 捕获 MinerU 的日志输出
        # standalone_mode=False 让 click 不调用 sys.exit()
        with contextlib.redirect_stdout(output_buf), contextlib.redirect_stderr(output_buf):
            mineru_main(args=args, standalone_mode=False)
    except click.exceptions.Exit as e:
        exit_code = e.exit_code
    except Exception as e:
        self.logger.error(f"MinerU解析异常: {e}")
        exit_code = 1

    # 打印日志到主进程 logger
    for line in output_buf.getvalue().splitlines():
        self.logger.info(f"MinerU: {line}")

    return exit_code
```

**技术要点**：
- **Python API 替代 subprocess**：整个调用在同一 Python 进程内，不存在 GBK→UTF-8 编码转换问题
- **click 的 standalone_mode=False**：避免 MinerU CLI 内部的 `sys.exit()` 提前终止主进程
- **contextlib.redirect_stdout**：捕获 MinerU 输出到 StringIO，再统一打印到项目 logger
- **CPU 模式友好**：MinerU pipeline 模式在纯 CPU 环境也能正常运行

def split_and_merge(self, sections, max_length, min_length):
    """切分过长章节，合并过短章节"""

    # 1. 切分过长章节
    current_sections = []
    for section in sections:
        current_sections.extend(self.split_long_section(section, max_length))

    # 2. 合并过短章节（贪心累加算法）
    final_sections = self.merge_short_section(current_sections, min_length)

    return final_sections

def split_long_section(self, section, max_content_length):
    """使用RecursiveCharacterTextSplitter切分长内容"""
    title = section.get('title')
    body = section.get('body')

    total_length = len(title) + len(body)
    if total_length <= max_content_length:
        return [section]

    # 使用LangChain的递归切分器
    text_splitter = RecursiveCharacterTextSplitter(
        chunk_size=max_content_length,
        chunk_overlap=0,
        separators=["\n\n", "\n", "。", "！", "？", "；", ".", "!", "?", ";", " ", ""],
        keep_separator=False
    )

    texts = text_splitter.split_text(body)

    sub_sections = []
    for index, text in enumerate(texts):
        sub_sections.append({
            "title": f"{title}-{index + 1}",
            "body": text,
            "file_title": section.get('file_title'),
            "parent_title": section.get('parent_title'),
            "part": f"{index + 1}"
        })

    return sub_sections

def merge_short_section(self, current_sections, min_content_length):
    """贪心累加算法合并短章节"""
    current_section = current_sections[0]
    final_sections = []

    for next_section in current_sections[1:]:
        same_parent = (current_section['parent_title'] == next_section['parent_title'])

        if same_parent and len(current_section.get('body')) < min_content_length:
            # 合并body
            current_section['body'] = (
                current_section.get('body').rstrip() + "\n\n" + next_section.get('body').lstrip()
            )
            current_section['title'] = current_section['parent_title']
            current_section['part'] = 0
        else:
            final_sections.append(current_section)
            current_section = next_section

    final_sections.append(current_section)

    # 重新编号part
    return self._renumber_parts(final_sections)
```

## 7. 面试高频问题与回答

### 7.1 项目介绍类

**Q1: 请简单介绍一下这个项目？**

**回答要点**：
> 这是一个基于 RAG 技术的智能知识库系统。系统采用 LangGraph 工作流编排，支持文档自动化导入和智能知识问答两大核心功能。
>
> 文档导入流程包含 PDF 解析（MinerU Python API，解决中文路径编码）、图片描述提取（Qwen3-VL）、文档切分、商品名识别、向量化（BGE-M3，本地 CPU 部署）、导入 Milvus。
>
> 知识查询流程采用三路检索架构——向量检索、HyDE 假设文档检索、网络搜索并行，通过 RRF 算法融合，再用 BGE-Reranker 重排序，最后根据 enable_agent_mode 开关选择 ReAct Agent 多轮 Tool Calling 或普通 LLM 单次调用生成答案。
>
> 技术上，后端使用 FastAPI + LangGraph，向量模型 BGE-M3（本地 CPU），LLM 用通义千问，向量数据库 Milvus。我主要负责 LangGraph 工作流设计、Agent 智能体实现和后端核心开发。

**Q2: 为什么选择 LangGraph 而不是直接用 LangChain？**

**回答要点**：
> 1. **状态管理**：LangGraph 提供 TypedDict 状态管理，节点间状态传递更清晰
> 2. **条件路由**：支持复杂的条件分支，比如商品名确认后的路径判断
> 3. **并发执行**：多路检索节点可以自动并发执行
> 4. **可视化**：可以打印工作流的 ASCII 图，便于调试
> 5. **循环支持**：支持循环结构，Agent 的多轮推理天然适合

**Q3: 为什么加了 ReAct Agent 功能？和原来的 RAG 有什么区别？**

**回答要点**：
> 原来的 RAG 是"**检索一次，回答一次**"——不管检索结果够不够，LLM 只能基于那批文档回答。如果文档不够，就容易幻觉。
>
> ReAct Agent 是"**边想边查，查完再想**"——LLM 先看自己需要哪些信息，不够就主动调用工具补充（知识库、联网搜索、价格查询等），最多 5 轮。这样回答质量显著提升，特别是价格、产品对比这类需要多源综合的问题。
>
> 我做了 enable_agent_mode 开关，Agent 和普通 LLM 模式可以零成本切换。

### 7.2 Agent / Function Calling 类 🆕

**Q4: 项目中的 Agent 智能体是如何实现的？**

**回答要点**：
> 我自研了一个 ReActAgent 引擎，核心是多轮循环：
>
> 1. 初始化 messages（system prompt + user query）
> 2. 进入 for turn in range(max_turns) 循环（默认 5 轮）
> 3. 调 LLM（带 tools schema，让 LLM 自己决定要不要调工具）
> 4. 如果 LLM 返回了 tool_calls → 遍历执行每个工具，把结果加到 messages → 继续循环
> 5. 如果 LLM 没返回 tool_calls → 说明它认为信息够了，直接输出答案，循环结束
> 6. 超过 max_turns → 取最后一条内容兜底
>
> LLM 调用走的是 httpx 直接 POST /chat/completions，不走任何框架，这样更可控、更容易 debug。

**Q5: Function Calling 原理是什么？**

**回答要点**：
> Function Calling（现在叫 Tool Calling）是 LLM API 提供的能力：
>
> 1. 调用时在 payload 里加 `tools` 参数，告诉 LLM 有哪些工具可用（名字、描述、参数 schema）
> 2. LLM 思考后，如果觉得需要调工具，会返回 `tool_calls` 字段，里面是 JSON 格式的工具名和参数
> 3. 客户端（Agent）拿到后，自己去执行对应的工具
> 4. 把工具执行结果作为 `role: "tool"` 的 message 加回 messages
> 5. 再次调用 LLM，LLM 看到工具结果后继续思考或输出最终答案
>
> 本质上就是一个"LLM 出指令 → 客户端执行 → 结果回喂"的循环。

**Q6: 如何设计和注册自定义 Agent 工具？**

**回答要点**：
> 我设计了 AgentTool 基类，每个工具只需继承它、实现 4 个东西：
>
> ```python
> class MyTool(AgentTool):
>     name = "my_tool"          # 唯一标识
>     description = "用来干嘛"    # 告诉 LLM 什么时候用
>     parameters = {...}        # JSON Schema 参数定义
>     def run(self, **kwargs):  # 子类必实现
>         return "结果"
> ```
>
> tools_json_schema() 方法会自动把这三样拼成 Function Calling 需要的 schema。
> safe_run() 包装了 run()，自动捕获异常和 JSON 序列化。
>
> 注册两种方式：直接传给 ReActAgent 构造函数，或者通过 ToolRegistry.register() 注册。

**Q7: Agent 的 system prompt 是怎么写的？**

**回答要点**：
> Agent 的 system prompt 要做三件事：
> 1. **角色定位**：你是专业的产品技术支持助手
> 2. **行为规范**：优先使用已检索的本地文档，需要实时信息时再调联网搜索，不确定时诚实说不知道
> 3. **格式约束**：用中文回答，结构化，引用来源
>
> 另外在构建 initial messages 时，会把商品名拼进 system prompt（"当前用户询问的产品：xxx"），让 Agent 回答时有上下文。

**Q8: Agent 达到 max_turns 还没结束怎么办？**

**回答要点**：
> 这是常见问题。我的处理策略：
> 1. **兜底**：for/else 语法——正常 break 结束后会走 else，取最后一条 content 作为最终答案
> 2. **系统提示**：在 system prompt 里告诉 LLM"尽量少轮次，信息够了就直接回答"
> 3. **工具结果压缩**：工具返回的内容不要太长，避免 LLM 上下文塞满
> 4. **实际观察**：大部分问题 2-3 轮就结束了，5 轮只是兜底上限

### 7.3 技术深度类

**Q9: BGE-M3 混合向量是什么？为什么要用混合向量？**

**回答要点**：
> BGE-M3 是一个能同时生成稠密向量和稀疏向量的模型。
>
> **稠密向量**是 1024 维的浮点向量，通过深度神经网络编码文本的语义信息，擅长语义理解，能匹配同义词和近义词。
>
> **稀疏向量**是词袋模型，类似于 BM25，每个 token 有一个权重值，擅长精确关键词匹配，如型号、专有名词。
>
> 混合检索结合了两者的优势：搜索 "RS-12万用表" 时，稀疏向量保证匹配到 "RS-12" 这个精确型号，稠密向量理解 "万用表" 的语义。Milvus 的 WeightedRanker 会融合两路结果，我们配置的权重是各占 50%。而且 BGE-M3 可以本地 CPU 部署，零 API 成本。

**Q10: 解释一下 RRF 融合算法？**

**回答要点**：
> RRF (Reciprocal Rank Fusion) 是倒数排名融合算法，用于合并多个排序结果。
>
> **公式**：`score(d) = Σ weight_i / (k + rank_i(d))`
>
> - d 是待评分的文档
> - i 是第 i 路检索
> - weight_i 是第 i 路的权重
> - rank_i(d) 是文档 d 在第 i 路中的排名
> - k 是平滑参数，通常设为 60
>
> **优势**：
> 1. 不需要考虑不同检索结果的分数分布差异
> 2. 算法简单，计算高效
> 3. 对异常值不敏感
>
> 在我们的项目中，向量检索和 HyDE 检索权重都是 1.0，网络搜索权重是 0.7。原来有知识图谱检索也是 0.7，但后来去掉了。

**Q11: 什么是 HyDE 检索？**

**回答要点**：
> HyDE (Hypothetical Document Embeddings) 是假设文档嵌入技术。
>
> **流程**：
> 1. 用户提问："RS-12万用表如何测电压？"
> 2. LLM 生成假设性答案文档："要测量直流电压，首先将万用表拨到..."
> 3. 对假设文档进行向量检索
> 4. 返回与假设文档语义相近的文档片段
>
> **原理**：假设文档包含了用户问题想要的信息，因此与假设文档相似的文档很可能也包含相关信息。
>
> **效果**：在模糊问题或概念性问题上效果明显，能提升召回率。

**Q12: 什么是断崖检测截断？**

**回答要点**：
> 断崖检测是我们实现的一个动态确定文档数量的算法。
>
> **原理**：重排序后的文档按分数降序排列，从第 5 个文档开始，逐对检查相邻文档的分数差距。如果绝对差距 >= 0.3 或相对差距 >= 50%，则认为出现"断崖"，在此位置截断。
>
> **示例**：
> - 文档 1-5 分数：0.95, 0.93, 0.89, 0.87, 0.82
> - 文档 6 分数：0.35
> - 差距：0.82 - 0.35 = 0.47 > 0.3 → 截断
>
> **优势**：避免低分文档混入，同时避免固定 Top-K 的机械性，根据分数分布动态确定保留数量。

### 7.4 问题解决类

**Q13: 遇到过什么技术难点？是怎么解决的？**

**回答示例一：PDF 中文路径编码问题** 🆕
> **问题**：原来用 subprocess 调用 MinerU 命令行解析 PDF，当文件路径包含中文（如 "万用表的使用.pdf"）时，Windows 下 GBK 编码和 MinerU 内部的 UTF-8 冲突，报 UnicodeDecodeError。
>
> **解决方案**：从 subprocess 改成 Python API 直接调用 `mineru.cli.client.main`。用 click 的 `standalone_mode=False` 避免 CLI 进程退出，用 `contextlib.redirect_stdout` 捕获输出。这样整个调用都在同一个 Python 进程里，不存在编码转换问题。
>
> **额外收获**：backend 也从 hybrid-engine（需 GPU）改成了 pipeline（CPU 模式），本地电脑就能跑。

**回答示例二：Agent MCP 调用 404/500 错误** 🆕
> **问题**：原来用 `agents.mcp.MCPServerStreamableHttp` 这个异步 SSE 库调 DashScope 百炼的 WebSearch MCP，连接不稳定，经常 404 或 500。而且在同步 LangGraph 节点里要用 `asyncio.run()` 包裹，很别扭。
>
> **解决方案**：改成纯 httpx 同步调用 MCP JSON-RPC。先 tools/list discover 可用工具，再 tools/call 执行搜索。代码更短（约 30 行 vs 原来的 80 行），异常直接捕获不崩溃。
>
> 这让我对 MCP 协议本身也理解更深了。

**回答示例三：商品名误判问题**
> **问题**：LLM 提取商品名时可能误判，如把 "万用表测量电阻" 误认为商品名。
>
> **解决方案**：设计了三级过滤机制
> 1. **向量对齐**：对每个提取名称进行 Milvus 检索，获取真实商品名和相似分数
> 2. **评分对齐**：score >= 0.7 放入 confirmed，0.6-0.7 放入 options，< 0.6 丢弃
> 3. **分数差异过滤**：如果 confirmed 中有多个商品，过滤掉与最高分差距 > 0.15 的误判商品
>
> 这样既保证了召回率，又控制了精确度。

**Q14: 如何保证系统的高可用？**

**回答要点**：
> 1. **模型单例**：BGE-M3、BGE-Reranker 使用单例模式，避免重复加载
> 2. **批量操作**：Milvus 批量插入，减少网络往返
> 3. **异常处理**：LLM JSON 解析失败时进行清洗和重试
> 4. **降级策略**：商品名确认失败时返回澄清选项，而非直接报错；MCP 搜索失败时跳过不影响主流程
> 5. **资源清理**：SSE 队列在 finally 块中清理，防止内存泄漏
> 6. **Agent 兜底**：max_turns 达到上限后取最后一条内容，不会返回空

### 7.5 设计思考类

**Q15: 如果让你重新设计这个系统，你会做哪些改进？**

**回答要点**：
> 1. **缓存层**：添加 Redis 缓存热门问题和答案
> 2. **对话摘要**：长对话使用 LLM 生成摘要，而非简单截断
> 3. **Agent 增强**：给 Agent 加记忆（短期/长期）、更多工具、多 Agent 协作
> 4. **分布式部署**：使用 Kubernetes 实现水平扩展
> 5. **可观测性**：集成 OpenTelemetry 实现分布式追踪
> 6. **A/B 测试**：对比不同检索策略和 Agent 策略的效果
> 7. **向量数据库分区**：按商品名分区，加速检索

**Q16: 多路检索之间是如何协同的？**

**回答要点**：
> 多路检索通过 LangGraph 的并发机制协同。main_graph.py 中用 `Send` 把三个检索节点并行启动（hybrid_vector_search、hyde_vector_search、web_mcp_search），然后用 join 节点等全部完成后再进入 RRF 融合。
>
> 这样设计的好处是：三个检索互不阻塞，总耗时取决于最慢的那一路，而不是三路之和。

**Q17: 什么情况下 Agent 会多轮调用工具？举个例子？** 🆕

**回答要点**：
> 当一个问题涉及多方面信息时。比如用户问 "RS PRO RS-12 数字万用表 最新价格是多少？怎么测量直流电压？"
>
> - Turn 1：LLM 判断需要两个信息源，同时发起 get_realtime_price 和 search_knowledge_base 两个 tool_calls
> - 拿到结果后 Turn 2：LLM 判断信息已足够，直接综合输出答案
>
> 再比如用户问 "万用表 A 和 B 哪个好？"，Agent 可能先 compare_products，发现信息不够再 search_web 补充最新评测，最后综合回答。
